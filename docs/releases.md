# Выпуск Shooter

## Сборка для macOS

В Godot 4.7.2 установи шаблоны экспорта той же версии через «Редактор → Управление шаблонами экспорта». Из корня проекта запусти:

```bash
./scripts/build-macos.sh
```

Скрипт собирает универсальный `Shooter.app` для Apple Silicon и Intel в корне проекта. Если в родительской папке есть `macos-4.7.2.stable.zip`, скрипт использует его и сохраняет приложение в `../Builds/`. Если Godot лежит в другом месте, укажи путь к исполняемому файлу через `GODOT_BIN`.

## Нумерация версий и патчи для macOS

Версия задаётся в `config/version` в `project.godot`. Главное меню показывает запущенную версию игры, а сведения macOS показывают версию полной сборки.

| Изменение | Следующая версия | Формат выпуска |
| --- | --- | --- |
| Исправление или небольшая доработка внутри текущей серии | `1.1.0 → 1.1.1` | PCK-патч, если обновление совместимо с базой |
| Новая карта, режим или заметное обновление игры | `1.1.0 → 1.2.0` | Полный `Shooter.app` и новая база для патчей |
| Крупный выпуск с переработкой основных механик | `1.2.0 → 2.0.0` | Полный `Shooter.app` и новая база для патчей |

Обновление Godot, настроек запуска или нативных компонентов, а также несовместимое изменение сетевого протокола требуют полной сборки. Для LAN используй одинаковую версию игры у всех участников.

Для каждого выпуска выбери формат обновления до замены `Shooter.app` в папке проекта. Для совместимого исправления подготовь патч от точного PCK той сборки, которая уже установлена у игроков. Для нового базового выпуска собери приложение с `--archive-base` и сохрани его вместе с PCK и файлом версии движка. Загрузчик сверяет SHA-256 базового PCK, поэтому для патча нужна копия именно выпущенного файла.

1. Собери и сохрани полную базовую версию командой `./scripts/build-macos.sh --archive-base`. В `releases/` появятся точная копия PCK из приложения и файл `.pck.engine` с версией Godot. Храни оба файла вместе с выпущенным приложением.
2. Для первого исправления увеличь `config/version` до `1.1.1` и выполни:

   ```bash
   ./scripts/build-macos.sh --patch releases/Shooter-1.1.0-base.pck
   ```

   Скрипт создаст `Shooter-1.1.0-to-1.1.1.pck` и соседний `.pck.cfg`. Патчи накопительные. Если `1.1.2` собран от той же базы, его можно сразу запустить поверх `1.1.0`.
3. Передай оба файла патча вместе. В Shooter.app 1.2.12 и новее открой в главном меню «Обновление» → «Выбрать .pck». После проверки игра сохранит файлы, перезапустится и будет использовать патч при следующих запусках.

   Для разовой проверки через терминал можно явно указать файл патча:

   ```bash
   open -n -a "$PWD/Shooter.app" --args -- --shooter-patch "$PWD/releases/Shooter-1.1.0-to-1.1.1.pck"
   ```

   Игра проверяет версию и контрольные суммы перед загрузкой. Номер патча виден в меню. Запуск без аргумента открывает базовую версию. Загружай патчи из источника, которому доверяешь, поскольку PCK может содержать код игры.

## Публикация патчей на GitHub

Публичное хранилище обновлений Shooter находится в разделе [GitHub Releases](https://github.com/gluhman/shooter-piu-piu/releases). Локальная папка `releases/` служит для хранения базовых PCK и результатов сборки.

1. Собери патч от архивного PCK выпущенного приложения.
2. Создай стабильный релиз с тегом `vX.Y.Z` для версии патча. Приложи `Shooter-<база>-to-<версия>.pck` и одноимённый `.pck.cfg` в **Assets** одного релиза. Если обновление подготовлено для нескольких баз, приложи отдельную пару для каждой.
3. После публикации открой «Обновление» → «Проверить GitHub» в приложении нужной базовой версии и проверь предложенный номер.

Игра просматривает последние 100 релизов и предлагает наибольшую версию среди полных комплектов для своей базы. Для установки версия должна быть выше запущенной. Скачивание и перезапуск начинаются после выбора «Скачать и установить». Размер PCK для скачивания из игры ограничен 1 ГиБ. GitHub принимает файлы релиза размером менее 2 ГиБ. [Ограничения GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases).

Размер патча зависит от того, какие ресурсы Godot заново импортировал при сборке. Даже небольшая правка может дать патч в десятки мегабайт. [Формат патчей Godot](https://docs.godotengine.org/en/stable/tutorials/export/exporting_pcks.html).

### Локальная база 1.2.12

В `releases/` сохранена точная копия PCK из `Shooter.app` версии 1.2.12 и файл версии движка. Для следующего совместимого исправления после повышения версии используй:

```bash
./scripts/build-macos.sh --patch releases/Shooter-1.2.12-base.pck
```

Проверь, что после установки и перезапуска главное меню показывает версию патча. Тестовые PCK и их `.pck.cfg` храни в `releases/test/`. Выбранный в меню патч загружается при следующих запусках. Для повторной проверки с базовой версией сначала закрой игру и перенеси `user://patches/active.cfg` из каталога пользовательских данных.

## Что загружается при запуске

Сначала открывается лёгкая сцена с логотипом Shooter и полным роликом в стиле Half-Life 2 длительностью около 12 секунд. Заставка воспроизводит дорожку из авторского ролика с громкостью музыки. Esc пропускает заставку и останавливает её звук. Музыка меню начинается после перехода. Пока заставка на экране, Godot в фоне загружает модель и анимации бойца, растительность и звук АК-47. Сцена меню загружается в основном потоке с уже подгруженными ресурсами. После перехода в меню игра заранее подгружает общие текстуры карт и звуки АК-47 для первого матча. Ресурсы выбранной карты, дополнительные модели оружия, навигация ботов и подготовка первого кадра остаются на экране загрузки матча.

Для версии 1.2.5 нужна полная сборка приложения. В этой версии изменилась стартовая сцена проекта.

## Перед отправкой в основную ветку

Основная ветка проекта — `main`. Проверка также настроена для имени `master`.

1. Увеличь `config/version` в `project.godot` относительно целевой ветки.
2. Добавь в начало [журнала изменений](../CHANGELOG.md) заголовок `## X.Y.Z` с тем же номером и опиши изменения списком. Оставь записи предыдущих выпусков.
3. Добавь или обнови содержательный Markdown-документ в `docs/`. При изменении ассетов обнови [каталог ассетов](assets.md) и сведения об источниках рядом с ресурсами.
4. Включи версию, журнал и документацию в отправляемые коммиты. Проверь их относительно актуальной основной ветки.

   ```bash
   git fetch origin
   python3 scripts/check-release.py --base origin/main HEAD
   ```

Для локальной проверки нужен Python 3. Чтобы Git отклонял прямой push при ошибке, установи хук и проверку из корня проекта. Если у репозитория уже есть свой `pre-push` или настроен `core.hooksPath`, добавь вызов к существующей настройке.

```bash
hooks_dir="$(git rev-parse --git-path hooks)"
install -m 644 scripts/check-release.py "$hooks_dir/check-release.py"
install -m 755 scripts/git-hooks/pre-push "$hooks_dir/pre-push"
```

GitHub Actions запускает проверку `Release metadata` в PR и после прямого push. Чтобы правило действовало для всех участников, владелец репозитория после первого запуска проверки должен потребовать PR, успешный статус `Release metadata` и актуальность ветки относительно `main` в настройках защиты. [Правила защиты веток GitHub](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets).
