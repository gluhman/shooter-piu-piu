# Выпуск Shooter

## Сборка для macOS

В Godot 4.7.2 установи шаблоны экспорта той же версии через «Редактор → Управление шаблонами экспорта». Из корня проекта запусти:

```bash
./scripts/build-macos.sh
```

Скрипт собирает универсальный `Shooter.app` для Apple Silicon и Intel в корне проекта. Если в родительской папке есть `macos-4.7.2.stable.zip`, скрипт использует его и сохраняет приложение в `../Builds/`. Если Godot лежит в другом месте, укажи путь к исполняемому файлу через `GODOT_BIN`.

## Нумерация версий, базы и совместимость

Версия задаётся в `config/version` в `project.godot`. Главное меню показывает запущенную версию игры, а сведения macOS показывают версию полной сборки.

Каждая серия обновлений начинается с полной базы `X.Y.0`. Патчи меняют только `Z`: `1.3.0 → 1.3.1 → 1.3.2`. База и патчи одной серии образуют один release train.

| Изменение | Следующая версия | Формат выпуска |
| --- | --- | --- |
| Совместимый hotfix или небольшая доработка | `1.3.0 → 1.3.1` | Накопительный PCK-патч |
| Новая карта, режим или заметное обновление | `1.3.x → 1.4.0` | Полный `Shooter.app` и новая база |
| Несовместимость с клиентом, сетью или средой запуска | `1.x.y → 2.0.0` | Полный `Shooter.app` и новая база |

Полная база обязательна при обновлении Godot, нативных компонентов, экспортных настроек или сетевого протокола. Также создавайте следующую базу до того, как серия превратится в длинную цепочку hotfix: при крупном контентном обновлении либо после примерно десяти пользовательских патчей. Для LAN все участники должны иметь одну версию; для интернет-комнат клиент и сервер обязаны принадлежать к одной совместимой серии.

### Имена PCK

Для новых серий имя патча содержит только итоговую версию: `Shooter-1.3.2.pck` и `Shooter-1.3.2.pck.cfg`. База не указывается в имени, поэтому пользователь не видит громоздкие названия вида `1.2.14-to-1.2.113`.

Совместимость не определяется именем файла. В `.pck.cfg` хранится `base_version` и SHA-256 базового PCK; загрузчик сверяет их до подключения патча. Патч от другой базы безопасно отклоняется с сообщением о несовместимости.

Формат `Shooter-<база>-to-<версия>.pck` считается устаревшим. Он сохраняется только для переходного патча, который должен обновить уже выпущенный загрузчик 1.2.14. Загрузчик после этого перехода распознаёт оба формата, но новые релизы публикуются только с коротким именем.

Для каждого выпуска выбери формат обновления до замены `Shooter.app` в папке проекта. Для совместимого исправления подготовь патч от точного PCK той сборки, которая уже установлена у игроков. Для нового базового выпуска собери приложение с `--archive-base` и сохрани его вместе с PCK и файлом версии движка. Загрузчик сверяет SHA-256 базового PCK, поэтому для патча нужна копия именно выпущенного файла.

1. Собери и сохрани полную базовую версию командой `./scripts/build-macos.sh --archive-base`. В `releases/` появятся точная копия PCK из приложения и файл `.pck.engine` с версией Godot. Храни оба файла вместе с выпущенным приложением.
2. Для первого исправления увеличь `config/version` до `1.3.1` и выполни:

   ```bash
   ./scripts/build-macos.sh --patch releases/Shooter-1.3.0-base.pck
   ```

   Скрипт создаст `Shooter-1.3.1.pck` и соседний `.pck.cfg`. Патчи накопительные: `1.3.2`, собранный от той же базы `1.3.0`, можно установить сразу поверх `1.3.0`.
3. Передай оба файла патча вместе. В Shooter.app 1.2.12 и новее открой в главном меню «Обновление» → «Выбрать .pck». После проверки игра сохранит файлы, перезапустится и будет использовать патч при следующих запусках.

   Для разовой проверки через терминал можно явно указать файл патча:

   ```bash
   open -n -a "$PWD/Shooter.app" --args -- --shooter-patch "$PWD/releases/Shooter-1.3.1.pck"
   ```

   Игра проверяет версию и контрольные суммы перед загрузкой. Номер патча виден в меню. Запуск без аргумента открывает базовую версию. Загружай патчи из источника, которому доверяешь, поскольку PCK может содержать код игры.

## Публикация патчей на сервер обновлений

Клиент получает манифест из `http://51.250.79.77/shooter/manifest.json`. Zoraxy направляет этот путь на статический backend, который читает файлы из `/opt/shooter-updates/releases` на сервере обновлений. Локальная папка `releases/` служит для хранения базовых PCK и результатов сборки.

Для нового патча сначала собери `Shooter-<версия>.pck` и одноимённый `.pck.cfg` от архивной базы. Затем загрузите их в отдельный каталог версии на сервере, например:

```text
/opt/shooter-updates/releases/1.3.2/Shooter-1.3.2.pck
/opt/shooter-updates/releases/1.3.2/Shooter-1.3.2.pck.cfg
```

После сверки SHA-256 обновите `manifest.json` одним атомарным переименованием временного файла. Манифест содержит только относительные пути к PCK и `.cfg`, размер PCK, целевую и базовую версии, контрольную сумму и краткий changelog. Не публикуйте манифест раньше обоих файлов: клиент проверяет его первым.

```json
{
  "channel": "stable",
  "base_version": "1.3.0",
  "version": "1.3.2",
  "pck": "1.3.2/Shooter-1.3.2.pck",
  "cfg": "1.3.2/Shooter-1.3.2.pck.cfg",
  "size": 419748,
  "sha256": "<sha256 PCK>",
  "notes": "Краткое описание изменений."
}
```

Перед публикацией проверьте `http://51.250.79.77/shooter/manifest.json`, заголовки и SHA-256 загруженного PCK. В приложении откройте «Обновление» → «Проверить обновления»: будут показаны версия, размер и поле `notes` из манифеста. Для установки версия должна быть выше запущенной; перед подключением дополнительно сверяются `base_version`, хеш базы и SHA-256 из `.pck.cfg`. Скачивание и перезапуск начинаются после выбора «Скачать и установить». Размер PCK для скачивания из игры ограничен 1 ГиБ.

Для каждой поддерживаемой базы сохраняйте две последние пары PCK и `.pck.cfg`. Архивный PCK базы и полную `Shooter.app` храните локально: они нужны для сборки следующего патча и не заменяются патчами.

Пока используется адрес по HTTP, поэтому защиту целостности обеспечивает `.pck.cfg`, но канал не защищён от подмены самого манифеста и файла конфигурации. До распространения за пределами доверенной сети следует перевести источник на HTTPS-домен и выпускать обновления только по нему.

Размер патча зависит от того, какие ресурсы Godot заново импортировал при сборке. Даже небольшая правка может дать патч в десятки мегабайт. [Формат патчей Godot](https://docs.godotengine.org/en/stable/tutorials/export/exporting_pcks.html).

### Кэш импорта для macOS-сборки

`build-macos.sh` сохраняет проверенный кэш импорта в `.shooter-export-cache/.godot`. Перед экспортом он копируется в изолированный снимок проекта, после успешного импорта — обновляется. Это не меняет состав PCK: Godot всё равно запускает `--import` и перепроверяет изменённые ресурсы. Каталог игнорируется Git; если нужно принудительно выполнить полный импорт, удалите только `.shooter-export-cache/`.

### Runbook: выпуск PCK-патча

Этот порядок применяется только к совместимому hotfix внутри одной базы. Полный выпуск, изменение нативной части или сетевого протокола требуют новой `Shooter.app` и следующей минорной/мажорной серии.

1. Увеличь только последнюю часть версии в `project.godot`, добавь запись в `CHANGELOG.md` и обнови эту документацию.
2. Проверь метаданные выпуска и собери накопительный патч от сохранённой базы:

   ```sh
   python3 scripts/check-release.py --base origin/main HEAD
   ./scripts/build-macos.sh --patch releases/Shooter-1.3.0-base.pck
   ```

3. Проверь, что SHA-256 PCK совпадает со значением `sha256` в соседнем `.pck.cfg`, затем запусти базовую app без звука с явным путём к патчу:

   ```sh
   Shooter.app/Contents/MacOS/shoot-container --headless --audio-driver Dummy -- \
     --shooter-patch "$PWD/releases/Shooter-1.3.1.pck" --shooter-version
   ```

   Успешная проверка выводит `Shooter: загружен патч <версия>` и `Shooter <версия>`.
4. Загрузите PCK и `.cfg` в новый каталог версии на сервере, проверьте обе контрольные суммы и только затем атомарно замените `manifest.json`. Коммит и тег отправляйте отдельно: они фиксируют исходный код, но не являются источником файлов обновления.

   ```sh
   scp releases/Shooter-1.3.1.pck releases/Shooter-1.3.1.pck.cfg \
     ansible@51.250.79.77:/opt/shooter-updates/releases/1.3.1/
   curl -fsS http://51.250.79.77/shooter/manifest.json | jq .
   ```

5. Скачайте PCK с публичного URL, повторите проверку из шага 3. В игре откройте «Обновление» → «Проверить обновления» и убедитесь, что показаны версия, размер и changelog патча.

Не загружайте архивный `Shooter-<версия>-base.pck` в публичный каталог: он остаётся локальным входом для следующей сборки. Для каждой поддерживаемой базы оставляйте на сервере две последние пары `.pck` и `.pck.cfg`.

### Устаревшая база 1.2.14 и переход

В `releases/` сохранена точная копия PCK из полной `Shooter.app` версии 1.2.14 и файл версии движка. Если нужно один раз обновить старый загрузчик до поддержки коротких имён, используй переходный режим:

```bash
./scripts/build-macos.sh --patch-legacy releases/Shooter-1.2.14-base.pck
```

Проверь, что после установки и перезапуска главное меню показывает версию патча. Тестовые PCK и их `.pck.cfg` храни в `releases/test/`. Выбранный в меню патч загружается при следующих запусках. Для повторной проверки с базовой версией сначала закрой игру и перенеси `user://patches/active.cfg` из каталога пользовательских данных.

Первый опубликованный патч этой базы — `Shooter-1.2.14-to-1.2.15.pck`; он проверяет полный путь обновления от DMG 1.2.14 до GitHub Releases. Следующий переходный патч также публикуется со старым именем, чтобы его увидел старый загрузчик. После установки нового загрузчика следующие патчи этой временной серии могут называться кратко, но следующая полноценная база должна стать `1.3.0`.

## Что загружается при запуске

Сначала открывается лёгкая сцена с логотипом Shooter и полным роликом в стиле Half-Life 2 длительностью около 12 секунд. Заставка воспроизводит дорожку из авторского ролика с громкостью музыки. Esc пропускает заставку и останавливает её звук. Музыка меню начинается после перехода. Пока заставка на экране, Godot в фоне загружает модель и анимации бойца, растительность и звук АК-47. Сцена меню загружается в основном потоке с уже подгруженными ресурсами. После перехода в меню игра заранее подгружает общие текстуры карт и звуки АК-47 для первого матча. Ресурсы выбранной карты, дополнительные модели оружия, навигация ботов и подготовка первого кадра остаются на экране загрузки матча.

Для версии 1.2.5 нужна полная сборка приложения. В этой версии изменилась стартовая сцена проекта.

## Перед отправкой в основную ветку

Основная ветка проекта — `main`. Проверка также настроена для имени `master`.

1. Увеличь `config/version` в `project.godot` относительно целевой ветки.
2. Добавь в начало [журнала изменений](../CHANGELOG.md) заголовок `## X.Y.Z` с тем же номером и опиши изменения списком. Оставь записи предыдущих выпусков.
3. Добавь или обнови содержательный Markdown-документ в `docs/`. При изменении ассетов обнови [каталог ассетов](assets.md) и сведения об источниках рядом с ресурсами.
4. Включи версию, журнал и документацию в отправляемые коммиты. Проверь их относительно актуальной основной ветки.

   ```bash
   git fetch origin
   python3 scripts/check-release.py --base origin/main HEAD
   ```

Для локальной проверки нужен Python 3. Чтобы Git отклонял прямой push при ошибке, установи хук и проверку из корня проекта. Если у репозитория уже есть свой `pre-push` или настроен `core.hooksPath`, добавь вызов к существующей настройке.

```bash
hooks_dir="$(git rev-parse --git-path hooks)"
install -m 644 scripts/check-release.py "$hooks_dir/check-release.py"
install -m 755 scripts/git-hooks/pre-push "$hooks_dir/pre-push"
```

GitHub Actions запускает проверку `Release metadata` в PR и после прямого push. Чтобы правило действовало для всех участников, владелец репозитория после первого запуска проверки должен потребовать PR, успешный статус `Release metadata` и актуальность ветки относительно `main` в настройках защиты. [Правила защиты веток GitHub](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets).
