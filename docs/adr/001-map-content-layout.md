# ADR 001: единый каталог содержимого карт

## Контекст

В проекте существовали две корневые папки с одним назначением: `game/maps/` для процедурных карт и `levels/` для authored-карты Breakwater. Из-за этого место для новой карты определялось не её ролью, а способом реализации, а ссылки на ресурсы расходились между двумя деревьями.

## Решение

Все материалы карт хранятся в `game/maps/`.

- `map_builder.gd` остаётся общим фасадом выбора и построения карты.
- `procedural/` содержит раскладки, которые создают геометрию кодом, и относящиеся к ним шейдеры.
- `breakwater/` содержит authored-сцену, дочерние сцены, скрипты и ресурсы Breakwater.

Корневая папка `levels/` удалена. Ссылки `res://` используют только новую структуру.

## Рассмотренные варианты

| Вариант | Решение |
| --- | --- |
| Оставить два корня | Отклонён: сохраняет неясную границу и дублирует место поиска карт. |
| Перенести процедурные карты в `levels/` | Отклонён: разрывает связь `map_builder.gd` с игровым модулем и смешивает общий код с ресурсами. |
| Собрать всё в `game/maps/` с подкаталогами по способу реализации | Принят: у карт один владелец, а различия реализации видны в структуре. |

## Последствия

Новая карта добавляется в `game/maps/<id>/` либо в `game/maps/procedural/`; `levels/` больше не используется. При перемещении карты необходимо обновить все `res://`-ссылки и открыть затронутые сцены в Godot, чтобы подтвердить доступность ресурсов.

Практический порядок добавления, проверки спавнов и навигации описан в [руководстве по картам](../maps.md).
